# AGENTS.md

Internal HSGQ RMA & WhatsApp log book web app (Indonesian team). React 18 + Vite 5, plain JSX (no TypeScript, no CSS framework). UI strings are Indonesian-first; code comments are mixed Indonesian/English — match the surrounding language.

## Commands
- `npm run dev` — Vite dev server on port 5173 (auto-opens browser)
- `npm run build` — outputs to `dist/`
- `npm run preview` — serve the build
- No test, lint, or typecheck scripts exist. Don't invent them; verification is `npm run build`.

## Architecture
- Entry point `src/main.jsx` gates the whole app behind Firebase Auth (`useAuth` → `Login` if signed out). You can't see the app without an account.
- Nearly all UI lives in `src/App.jsx` (~4200 lines): pages (Dashboard, RMA log, WA log, Unit History, Weekly Report, Settings, PCBA Inventory), shared components, i18n dict, and helpers. Smaller modules: `src/firebase.js`, `src/auth/` (AuthContext, Login), `src/context/ThemeContext.jsx`, `src/components/UserCenter.jsx`.
- The empty `rma-hsgq/` directory at repo root is accidental; leave it alone.

## Data layer (critical)
- All reads/writes go through `storeGet(key, fallback)` / `storeSet(key, value)` in `src/firebase.js`. Never touch Firestore or localStorage directly for app data.
- Backend is Firestore collection `hsgq_rma_app`, one doc **per dataset** storing a single `value` field (whole arrays as one doc): `rma_entries_v2`, `wa_entries_v2`, `master_data_v2`, `pcba_data_v1`. If Firebase isn't configured, these same keys fall back to localStorage transparently.
- The Firestore config in `src/firebase.js` is hardcoded (no `.env`). `isUsingFirebase` is true unless a value contains `"GANTI"`.
- Master data (engineers, statuses, etc.) defaults live in `DEFAULT_MASTER` in App.jsx and are user-editable via Settings; statuses are free strings, not enums.

## Conventions to preserve
- Dates: store as ISO `yyyy-mm-dd`, display via `fmtDate()` as `dd/mm/yyyy`. Ticket numbers are `RMA-yyyymmdd-NNN` (and WA analog), generated by `genTicket()`.
- Styling is inline styles + CSS variables referenced through the `T` token map (e.g. `T.cyan`, `T.panel`) or raw `var(--x)` in global.css. Don't introduce a styling library.
- i18n: all user-visible strings live in the `I18N` object at the top of App.jsx with **id / en / zh** blocks. Add new strings to all three; language choice is stored in `localStorage.hsgq_language`. Theme is `localStorage.hsgq_theme` + user profile.
- Charts use `recharts`; icons use `lucide-react`.

## Photo upload gotcha
`PhotoPickerCard` keeps selected `File` objects in a module-level in-memory `fileRegistry` Map and shows `URL.createObjectURL` previews. On save, `uploadRmaPhoto()` uploads to Storage at `rma_photos/{ticketNo}/{category}/{id}.{ext}` and persists **only metadata** `{id, name, url, size, uploadedAt}` in the ticket. Never store `File`, Base64, or blob URLs in Firestore/localStorage.
